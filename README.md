# Hairhaeyo

> 미용실 매출관리를 위한 개인 사업자 대상 운영관리 웹앱

Hairhaeyo는 고객, 예약, 시술 결제, 매출, 문자, 운영 업무를 한곳에서 관리하기 위한 **Next.js 기반 데스크톱 웹앱**입니다. 기존 관리 시스템의 기능 목록을 기준으로 업무 흐름을 다시 구성하고 있으며, 향후 Windows 설치형 앱으로 배포할 수 있도록 Tauri 기반도 함께 준비하고 있습니다.

## 이런 분을 위한 앱입니다

- 고객 정보를 빠르게 찾고 관리하고 싶은 미용실 사용자님
- 예약, 대기 고객, 시술 내역을 한 화면에서 확인하고 싶은 매장
- 현금·카드·포인트·이체 등 결제 내역과 매출을 정확하게 관리하고 싶은 사용자
- 단체 문자와 예약·결제 후 안내 문자를 체계적으로 운영하고 싶은 매장

현재 제품은 **개인 매장 사용자 1인 운영**을 기준으로 합니다. 여러 디자이너의 권한·인센티브를 관리하는 대신, 담당자와 판매자는 사용자로 자동 귀속하는 흐름을 사용합니다.

## 주요 기능

### 오늘 운영

- 오늘 대기 고객과 예약 현황 확인
- 오늘부터 글피까지 예약 건수 요약
- SMS 잔여 건수와 자동문자 상태 확인
- 공지, 가이드, FAQ 접근

### 고객 관리

- 고객명, 전화번호, 닉네임, 그룹, 메모 등 다양한 조건 검색
- 고객 기본정보와 시술·상품·포인트·예약 이력 조회
- 고객 등록·수정, 등급·그룹·방문 동기 관리
- 검색 결과 인쇄와 마케팅 대상 문자 발송

### 예약

- 월·일·기간별 예약 확인
- 고객·시술·시간을 연결한 예약 등록
- 개인 매장 단일 시간축 기반 예약 운영
- 예약 중복 허용·차단 및 알림 설정

### 결제·매출

- 회원·비회원 시술 결제 등록
- 현금, 현금영수증, 카드, 포인트, 이체, N페이, 지역페이 등 결제수단 관리
- 할인, VAT, 결제 수수료, 환불·조정, 샵 수익 반영
- 일별·월별 매출, 결제수단별 매출, 시술 유형별 매출 조회
- 매출 상세 인쇄와 CSV 출력

### 문자

- 개별·단체 SMS/LMS 작성 및 발송
- 예약 발송과 수신 거부 고객 제외
- 문자 바이트 수와 예상 차감 건수 확인
- 자주 쓰는 문구와 자동문자 설정

### 운영 관리

- 지출 항목과 지출 내역 관리
- 서비스·가격 카탈로그 관리
- 매출·지출 조정 및 인쇄
- 변경 이력과 데이터 정확성을 고려한 운영 흐름

## 실행하기

### 일반 사용자

현재 저장소는 개발용 웹앱입니다. 설치 파일이 제공되면 Windows에서 설치 후 Hairhaeyo 아이콘을 실행하는 방식으로 사용할 수 있습니다. Tauri 번들은 준비 중이며, 아직 공개 다운로드 링크는 제공하지 않습니다.

### 개발 환경

필요한 환경:

- Node.js 20 이상 권장
- npm
- Windows에서 Tauri를 실행하려면 Rust와 WebView2 환경

```bash
git clone <repository-url>
cd web
npm install
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

## 환경 변수

개발용 예시 파일을 복사해 사용합니다.

```bash
copy .env.example .env.development
```

`.env.development`에는 다음 값을 설정할 수 있습니다.

| 변수 | 설명 |
| --- | --- |
| `HAIRHAEYO_DEMO_MODE` | 데모 데이터·개발 모드 사용 여부 |
| `HAIRHAEYO_SESSION_SECRET` | 로그인 세션 서명용 비밀값 |

사용자 비밀번호는 초기값이 없습니다. 첫 실행 시 로그인 화면이 비밀번호 설정 화면으로 나타나며, 이후 변경은 설정 › 매장 · 사용자 계정에서 합니다.

비밀번호, 세션 비밀값, 고객 개인정보는 Git에 커밋하지 않습니다.

## 개발 명령어

| 명령어 | 용도 |
| --- | --- |
| `npm run dev` | Next.js 개발 서버 실행 |
| `npm run build` | 운영용 Next.js 빌드 |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm test` | Vitest 테스트 실행 |
| `npm run tauri:dev` | Tauri 개발 창 실행 |
| `npm run tauri:build` | Tauri 설치 파일 빌드 |
| `npm run tauri:info` | Tauri 환경 정보 확인 |

Tauri 배포 번들은 `tauri.conf.json`에서 활성화되어 있고 타깃은 `nsis`입니다. 설치 파일을 실제 배포하기 전에는 자동 업데이트와 데이터 백업 정책을 별도로 확정해야 합니다.

## 프로젝트 구조

```text
app/          Next.js App Router 페이지와 서버 액션
components/   화면별 React 컴포넌트와 테스트
lib/          도메인 로직과 공용 유틸리티
src-tauri/    Windows 데스크톱 앱 패키징 설정
FUNCTION.md   기존 시스템 기능 인벤토리와 추적성 기준
DESIGN.md     제품 UX·UI·Tauri 방향
```

주요 경로:

- `/login` 로그인
- `/` 오늘 대시보드
- `/customers` 고객 관리
- `/bookings` 예약
- `/sales` 결제·매출
- `/sales/transactions` 매출 내역
- `/messages` 문자
- `/operations` 지출·운영

## 데이터와 개인정보

Hairhaeyo는 고객 정보와 금액 데이터를 다루므로 다음 원칙을 따릅니다.

- 로그인한 사용자 계정의 권한을 기준으로 관리 화면을 보호합니다.
- 금액 계산과 거래 기록은 서버 측 도메인 로직을 기준으로 합니다.
- 차트, 표, CSV, 인쇄 결과는 같은 매출 집계 흐름을 사용합니다.
- 중복 결제, 수정 이력, 환불, VAT, 수수료, 포인트, 쿠폰, 샵 수익은 테스트 대상으로 취급합니다.
- 로컬 설치형 앱으로 배포할 경우 데이터 저장 위치, 백업, 복구, PC 교체 절차를 별도로 제공합니다.

외부 서비스의 계정 데이터는 공식 API 또는 허가된 내보내기 절차가 있을 때만 계정별로 가져옵니다. 사용자의 로그인 정보나 외부 DB 비밀번호를 앱에 하드코딩하지 않습니다.

## 기능 추적성

기존 시스템의 기능과 하위 기능은 [`FUNCTION.md`](FUNCTION.md)에 정리되어 있습니다. 화면을 단순화하더라도 기존 동작을 조용히 제거하지 않는 것을 원칙으로 하며, `[추가확인]` 항목은 실제 동작 검증 전까지 완료된 것으로 간주하지 않습니다.

제품 방향과 화면 설계는 [`DESIGN.md`](DESIGN.md)에서 확인할 수 있습니다.

## Vibecoding으로 만드는 과정

이 프로젝트는 요구사항과 기존 기능 인벤토리를 먼저 정리한 뒤, AI와 개발자가 함께 화면·도메인 로직·테스트를 빠르게 반복하는 **Vibecoding 방식**으로 개발하고 있습니다. AI가 만든 결과를 그대로 사용하지 않고, 기존 함수 목록과 실제 코드 흐름을 대조하고 타입 검사·자동화 테스트·빌드 검증을 거쳐 반영합니다.

즉, Vibecoding은 빠르게 시도하는 개발 방식이고, 개인정보·금액·권한처럼 중요한 부분은 명시적인 규칙과 테스트로 검증합니다.
