# 결제 등록 빠른 동선

## 범위

`FUNCTION.md` 3.1 시술 결제 등록을 유지하면서 `/sales?tab=payment`의 입력 동선을 고객 등록처럼 단순화한다.

## 화면

- 기준 화면: 1440px 폭, 이온2 FHD 노트북의 일반 작업 높이. 최소 지원 폭은 1280px.
- 첫 화면에는 날짜(오늘 자동), 이름, 휴대폰 뒷자리, 고객 확인 결과, 시술, 금액, 포인트, 결제 방식, 최종 결제 금액과 저장 버튼을 둔다.
- 이름과 휴대폰 뒷자리는 고객 식별 조합이며 중복을 허용하지 않는다.
- 두 값이 일치하면 `N번째 방문이에요`와 보유 포인트를 표시한다. 일치하지 않으면 인접한 `회원 등록` 동작을 보인다.
- 결제 방식은 단일 결제(기본 카드)와 분할 결제다. 분할 수단·VAT·수수료·지출은 분할 결제를 선택했을 때만 펼친다.
- 최종 결제 금액은 하단의 고정 요약 영역에 표시한다.

## 보존할 동작

- 서버의 불변 원장, 멱등성 키, 포인트 잔액 검증, VAT·수수료·매장 이익 계산, 환불/정정 이력은 변경하지 않는다.
- 결제 수단 합계와 최종 결제 금액은 동일한 `settleAmounts()` 계산을 사용한다.
- 비회원 포인트 사용·적립은 계속 차단한다.

## 상태와 검증

- 회원 일치, 미등록, 포인트 초과, 분할 합계 초과, 저장 실패 상태를 명확한 문장으로 표시한다.
- 고객 등록 시 이름+휴대폰 뒷자리 중복을 서버에서도 거절한다.
- 키보드 순서는 날짜 → 이름 → 휴대폰 뒷자리 → 시술 → 금액 → 포인트 → 결제 방식 → 저장이다.

## 검증

- 회원/미등록/포인트 초과/분할 결제/서버 오류 상태를 자동 테스트한다.
- 1440px와 1280px에서 Playwright로 한국어 밀도와 고정 요약 영역을 확인한다.
