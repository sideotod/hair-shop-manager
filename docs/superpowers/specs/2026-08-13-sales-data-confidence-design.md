# Sales Data Confidence Design

**Goal:** 원본 이관 데이터의 결손을 분석 결과처럼 보이지 않게 차단하고, 분리된 더미 데이터 환경에서만 매출 분석 UI/UX를 검증한다.

**Traceability:** `FUNCTION.md` §3.2 매출 조회(시술 유형별 매출, 결제 수단별 매출, 일별·월별 매출, VAT·결제 수수료·샵 수익), §3.5 매출·지출 조정/정산.

## Context

현재 Hairnury 이관 원장은 금액과 날짜는 보존하지만, 모든 행의 `details.serviceMajor`는 `미분류`, `paymentMethods`는 `other`, 시간은 동일한 UTC 시각이다. 이 값으로 시술·결제수단·시간대 분석을 제공하면 실제 운영 판단을 오도한다. `scripts/seed-analytics-dummy.sql`은 이 세 필드를 결정적으로 합성하지만 실제 원천을 복원하지 않는다.

## Decision

### Production/original-data path

- 서버가 기간의 결제 원장을 읽어 분석 차원별 신뢰도 상태를 계산한다.
- 서비스 분류가 `미분류`이거나 없으면 시술 카테고리 분석은 비가용이다.
- 결제수단이 `other`뿐이거나 없으면 결제수단 분석은 비가용이다.
- 이관 원장임을 나타내는 동일한 고정 시간만 있으면 시간대 분석은 비가용이다.
- 비가용 상태는 해당 차트·상세 보기·표를 숨기고, `원본 정보 없음` 제목, 이관 후 복원된다는 설명, 그리고 금액 기준 분석은 계속 정확하다는 안내를 표시한다.
- 총 매출, 실결제, 샵 수익, 객단가, 일/주/월/연도 추이, 요일별 방문, 고객 구성, 정산, CSV는 계속 원장 서버 집계를 사용한다. 금액이나 불변 원장을 수정하지 않는다.

### Demo/audit path

- 더미 적용 대상은 명시한 별도 SQLite 복제본뿐이다. 기본 `.data/hairhaeyo.sqlite`에는 적용하지 않는다.
- 실행 스크립트는 원본 DB를 복사한 뒤 복제본에만 기존 결정적 SQL을 적용한다.
- 실행 시 환경변수 또는 인자로 demo DB 경로를 명시하며, 앱도 그 경로가 명시된 경우에만 이를 연다.
- 더미 데이터가 켜진 화면은 분석을 검증할 수 있지만, 운영 데이터라고 주장하지 않는다. 감사 문서와 HTML 산출물에 “데모 데이터”임을 명시한다.

## UI behavior

- 서비스·결제수단·시간대는 각각 독립적으로 차단한다. 한 차원의 결손이 다른 차원의 표시를 막지 않는다.
- 차단 카드는 기존 카드의 위치와 폭을 유지해 1280px 이상 데스크톱 레이아웃을 흔들지 않는다.
- 안내는 색상만으로 상태를 전달하지 않고 텍스트 제목과 설명을 포함한다.
- 차단된 차트에는 드릴다운 버튼, 빈 비율, 합성된 순위나 추정치를 표시하지 않는다.
- 키보드 탐색 순서는 변하지 않으며, 비가용 카드는 버튼이 아니다.

## Data boundary

- `RevenueAnalyticsView`에는 신뢰도 상태를 명시적으로 전달한다. 클라이언트는 신뢰도를 계산하거나 금액을 재집계하지 않는다.
- 서버는 원장 범위에서 상태를 계산한다. UI, CSV, KPI, 정산은 이미 사용 중인 서버 집계를 공유한다.
- 실제 이관 시에는 원천 서비스명·결제수단·결제시각을 매핑한 importer로 이 상태를 해제한다. 이 작업은 이번 범위에서 구현하지 않는다.

## Testing and audit

- 단위 테스트: 원본 결손 데이터에서는 각 상태가 비가용이 되고, 정상 결제 레코드에서는 가용이 되는지 검증한다.
- 렌더링 테스트: 비가용 안내와 정상 차트가 각각 올바르게 표시되고, 금액 KPI/정산이 변하지 않는지 검증한다.
- 브라우저 감사: 원본 데이터와 분리된 더미 DB로 `sales-audit.md`의 모든 단계(초기 진입, 날짜·기간, KPI, 차트, 시술, 결제, 시간, 고객, 상세, loading/empty/error, 키보드, 1280px 데스크톱)를 캡처·검증한다.
- 감사 발견사항과 수정 후보는 `docs/audit/`의 HTML 보고서 하나에 스크린샷 링크와 함께 기록한다. 구현 수정은 이 보고 후 사용자 승인 범위에서만 진행한다.

## Non-goals

- 더미로 운영 원장을 덮어쓰거나 커밋하지 않는다.
- 실제 원천 데이터의 서비스·결제수단·시간 매핑을 추측해 구현하지 않는다.
- 모바일 UI를 추가하지 않는다.
